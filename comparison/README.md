## 共同知识主线

**概念 → 工具执行闭环 → 流程与决策 → 状态与记忆 → 检索与上下文 → 协作与协议 → 评测 → 部署与安全**，然后按兴趣延伸到应用形态、模型训练、研究与具身环境。

这不是要求新人先学完 49 点。第一轮先做出一个带工具的 Agent，再根据项目需要补状态、检索、评测或安全。Query、意图分流归入决策阶段，Harness 归入开发应用形态，操作边界归入安全交付；名词在同一张地图上有了位置。

## 三个看矩阵的例子

### 1. 理解 Agent 的执行机制

先比较 K01、K05、K06、K10、K11、K12。吴恩达课程在已审阅转录中有设计模式与工作流解释；Datawhale/HF 的对应研究记录有具体实现材料。两者可以搭配，不能用“谁的代码格子多”代替解释是否适合新人。

### 2. 设计可中断和恢复的工作流

重点比较 K13、K15–K18、K35–K36，而不是只看“有记忆”。LangGraph 已审阅材料涉及 checkpoint、人工修改状态、时间回溯和部署；Microsoft 研究记录涉及状态序列化及生产运行。再核验自己的请求隔离、存储和恢复测试。

### 3. “我听说 MCP 很重要，所以只学 MCP 可以吗”

两门 MCP 专题在 K27 集中，覆盖节点数少符合专题目标。要完成一个应用，还需要工具执行闭环、路由、状态、评测和操作边界。这正是共同主线比课程品牌列表更有用的地方。

## 如何解释表里的深度

**1：目录明确涉及；2：正文/转录或正文索引有解释；3：研究记录定位到具体实现或练习。—：当前未定位；?：资料不足。** 这是证据支持的下限，受采集范围影响，不是课程的固有分数，也不是跑通认证。所有正向判断均可进入证据账本继续核验。

当前不做统一百分比或综合排名：49 个粗粒度节点对不同目标的重要性不同，且有些节点只确认部分子主题。先选择相关阶段，再比较分布与证据，能比“覆盖了多少百分比”更可靠地支持选课。
