# 课程特征与体验评价的范围

本轮完成的是公开文字与代码静态审阅。没有逐课观看全部视频、提交作业、运行云服务、获取证书，也没有测量新手实际耗时。以下结论是可检查的教材属性，不冒充学习者完成课程的感受。

## 已经可以审阅的体验维度

| 维度 | 要读取的证据 | 可写的结论 | 不能据此声称 |
|---|---|---|---|
| 起点 | 前提说明与第一段代码 | 默认会Python/type hint/async/API凭证 | 零基础一定能跟上 |
| 连贯性 | 章节依赖、符号与案例变化 | 定义先于使用；同一项目贯穿或频繁切换 | 实际完成率高 |
| 操作负担 | setup、requirements、notebook、云账号 | 主路径需要云资源或模型下载 | 环境必然安装成功 |
| 反馈 | quiz、rubric、tests、sample output | 作业有无成功标准与失败解释 | 作业答案被实际验证 |
| 调试 | 错例、trace、error handling | 教材是否展示失败与定位过程 | 线上服务稳定 |
| 成本 | API与平台要求 | 免费文本不代表免费运行 | 实际账户费用 |
| 中文可读性 | 同版中英文正文逐段比对 | 某章节翻译滞后或术语跳变 | 全部中文章节质量一致 |
| 更新 | commit、changelog、模型名、依赖固定 | 当前获取版本及变更 | 任意未来版本仍然一致 |

## 本轮已观察的学习障碍

- HF：英文与中文欢迎页关于证书截止时间及框架名称存在差异。英文目录应作当前结构基准；具体差异见HF证据文档。不能把一处差异推成所有翻译失效。
- 微软：当前主路径依赖Azure/Foundry及模型资源，18课覆盖较广；它同时提供本地章节，但本地硬件和模型下载依然是学习负担。
- Anthropic：现在有系统课程而非只有工程文章；公开课中文字已获取。部分代码是教学片段或mock，不能复制一段就期待生产应用。
- OpenAI：SDK文档由最小例子串联工具、编排、会话与批准，阅读入口清楚；学习track仍是文档导航，缺一套连续作业与统一毕业标准。
- Datawhale/LangChain/DLAI/Berkeley：具体材料以各自研究文档为准，不能用课程封面和营销语代替正文审阅。

## 评价口径

结论应区分目录或简介、已获取正文与代码审阅、实际运行和作业验收等不同证据层次。实际运行结果应注明使用的系统、课程版本和依赖条件。

## 结论表达

例如：“从目录及代码看，这门课需要先会异步 Python”“正文解释了条件边，但没有在本节提供退款审批练习”。静态研究不能推出课程已完成、项目已跑通或学习者的实际耗时。

## 版本与资料维护

原始材料、provider/evidence 引用和 analysis 归纳分别保存。教程更新时应比对课程目录、模型名、依赖、云平台接入及权限接口，再修订结论并注明研究日期和版本。
